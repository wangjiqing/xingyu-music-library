# Agent 核对与资源关联约定

当前文件定义未来接口，尚未启动自动核对任务或配置模型密钥。

## 核对提案

任务以具体条目、字段和问题为单位。取证 Agent 实际读取来源，复核 Agent 检查证据与版本。结果可以是有依据的修改，也可以是“信息不足”或“存在冲突”。

提案建议包含以下字段：

```json
{
  "entry_id": "现有条目的稳定 ID",
  "base_revision": 1,
  "question": "需要核对的问题",
  "changes": [
    {"field": "year", "before": null, "after": 2000}
  ],
  "evidence": [
    {
      "url": "实际读取的页面地址",
      "locator": "页码、段落或署名位置",
      "accessed_at": "实际访问时间",
      "supports": "支持或反驳的具体主张",
      "excerpt": "必要的短摘录"
    }
  ],
  "result": "supported | conflicting | insufficient",
  "unresolved": [],
  "agent_run_id": "执行记录 ID"
}
```

示例年份仅用于说明格式，不代表任何条目的真实结论。

未来应用程序应先确认 `base_revision` 与当前条目一致，核对 `before` 值，再应用经过采纳的修改并递增修订。过期提案重新比较，不覆盖新资料。删除、合并或拆分条目需要保留旧 ID 与目标 ID 的映射。

公开证据可以放在 `data/evidence/` 或 PR 中，后续扩充 schema 后在条目中引用。运行日志、缓存、费用记录和模型凭据保存在私有位置，不进入静态网站。当前构建器拒绝未经约定的新字段，扩展时先修改校验及数据契约。

## 搜索无结果后的收录流程

目录页在搜索无结果时可将关键词带入 GitHub 收录请求。当前请求由维护者处理；静态 GitHub Pages 本身不能安全保存模型密钥或直接写入目录，因此网页不声称已自动联网检索。

后续可由 Agent 对收录请求检索网页并读取可访问来源，分别为年代、署名、关联作品和记忆主题生成带证据的字段提案。提案应包含实际访问时间、原文定位、支持的具体主张、冲突来源与不确定性。维护者为请求加上明确的处理标记后，受控任务才运行；Agent 建立草稿分支和 PR，现有校验通过后由维护者审阅并合并。不要因为搜索零结果就自动公开一条没有证据的新记录。

此工作流仍待选择并配置联网检索与模型服务凭据、执行预算和访问限制。模型密钥只能放在 Actions secrets 或专用服务端，不能放在网页、条目 JSON 或公开日志中。未经信任的 Issue 文本视为输入数据；运行任务需限制仓库权限、依赖和可写路径。GitHub Actions 负责格式与关系检查，维护者审阅事实后合并，Pages 自动更新。

## 音频关联

`audio_refs` 只接受 `aud-` 开头的 16—32 位十六进制资源 ID。它不包含对象存储 URL、桶名、对象键或访问凭据。私有映射可以记录资源 ID、录音身份、存储位置、格式、时长、校验值及版本确认状态。

Agent 可以提出文件匹配候选。名称、时长或音频指纹的匹配不能直接等同于版本核实。资源缺失时保持空列表，目录仍正常使用。
